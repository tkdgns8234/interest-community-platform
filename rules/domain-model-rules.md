# 도메인 모델 규칙

## 1. POJO 기반 설계
도메인 모델은 외부 프레임워크나 라이브러리에 의존하지 않는 순수 Java 객체(POJO)여야 합니다.
- `@Getter`, `@Builder` 등 Lombok은 필요에 따라 유연하게 사용 (쉽게 교체 가능한 수준)

## 2. 비즈니스 로직 내재화
도메인 모델은 비즈니스 로직을 포함해야 합니다. 단순한 데이터 구조체(Anemic Domain Model)가 되어서는 안 됩니다.

## 3. 캡슐화
도메인 모델은 관련된 속성과 행위를 하나의 단위로 캡슐화해야 합니다.

## 4. 불변성 활용
도메인 모델은 불변 객체(Immutable Object)를 활용하여 상태 변경을 명확히 표현해야 합니다.
- 식별자가 필요 없는 개념(값이 변경되어도 동일한 개체)은 Value Object로 설계합니다.

## 5. 유연한 설계
도메인 모델은 변경에 유연하게 대응할 수 있도록 설계되어야 합니다.

## 6. 명확한 경계
도메인 모델은 명확한 경계를 가지며, 다른 도메인 모델과의 상호작용을 최소화해야 합니다.
- Aggregate Root 간 직접 참조를 피하고, 미리 약속된 인터페이스나 이벤트를 통해 상호작용합니다.
- Aggregate Root 간 동기적 결합은 인터페이스를 통해 추상화하여 추후 API 통신이나 메시지 큐로 전환이 용이하도록 설계합니다.

## 7. 계층 독립성
도메인 모델은 저수준 모듈(Presentation Layer, Infrastructure Layer)에 종속되지 않아야 합니다.
